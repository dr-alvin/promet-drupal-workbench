# Delivery budgets and diagnostic improvements

The project schema accepts `deliveryBudget`; omission defaults to a 20h human engineering/technical QA target and 3h checkpoint. See [the unified prompt](unified-prompt.md) for configuration. Forecast scope is `total` by default or explicitly `remaining`; remaining-work forecasts with unknown actuals do not fabricate total effort. Targets are never substituted for forecasts. Human time is operator-reported, not inferred from command duration. An explicit project decision is required to change the target. Execution requires actual effort and forecast, checkpoint review when due, and a new reviewed plan after configuration changes. It pauses when the forecast does not fit. Keep execution batches bounded and update reported effort between batches; the toolkit cannot measure unreported human work during a running batch.

Static discovery caches sanitized repository evidence under `artifacts/cache`. The key covers source content (including untracked files), configuration, toolkit scripts/schemas, vendor installation metadata, extension metadata and configured external roots. Runtime calls and Git state are never reused. `--refresh` forces static recollection. Assessment refreshes PHP/Composer/Drush, the selected Drush command catalog, bootstrap, active extensions, pending database updates, config status and a configured identity probe. Execution recollects mutable runtime evidence before its existing sequential identity and step gates. Database version is not inferred from an unsupported status field; collect a project-specific read-only query if needed.

Only the read-only PHP and Composer probes overlap, using two workers. Drush probes and all mutation steps remain sequential. Docksal PHP uses `fin exec php`. Commands are selected from the returned Drush catalog; default JSON fields are discovered from actual status output. Empty `updatedb:status` with exit 0 and the verified “No database updates required.” diagnostic means no pending updates. Other empty or malformed structured output is a tooling failure. JSON is parsed before redaction; `token` module identifiers survive, credential values do not. Execution status is separate from scanner findings and parse failures. A reviewed `compatibilityCoverage` declaration must identify target, complete scope evidence and required check IDs; only valid completed checks discharge compatibility-unknown. This does not discharge release/UAT/recovery gates.

Browser readiness checks rendered document images across the capture width and explicitly configured `ready.requiredImages` selectors. Hidden variants are outside coverage. Required hidden images fail until setup/interactions reveal them. Bounded scrolling defaults to 20 increments, 10,000px and 5 seconds; configure `ready.scroll` for project requirements. Visible broken/unloaded images, missing required selectors, wrong URLs, authentication failures and incomplete captures still fail. Coverage diagnostics are written to `image-coverage.jsonl` and results. New implementation hashes invalidate previous baselines; use a new output directory and retain old failures.

Mark a small scenario set `critical: true`. Reference capture still establishes the entire configured catalog. Test runs the critical subset first; failure reports partial coverage and stops. After a passing critical subset, the complete required catalog runs. Explicit `--select` runs report partial coverage and cannot declare full verification passed. The image tag is derived from container build inputs; an existing matching local image is reused, and changed inputs cause a build. Removing the image also triggers a build.

Native audience reports share `result.json` and its normalized delivery budget. `scripts/revise_audit.py` publishes the Prometweb-specific historical estimate revision from an unchanged assessment plus current project budget into a new directory. It produces audience Markdown and optional DOCX files from one `revision.json`, then validates report hashes and equality with the original findings and gate. It refuses to overwrite an existing revision. Earlier schema-3.0 packets remain historical snapshots; the revision does not fabricate a new client scan.

Timings, static reuse, subprocess counts and failure categories are in context/results; the browser launcher adds `launcher-metrics.json` and the browser result records capture attempts and duration. Measurements are machine runtime, not billable human effort. The discovery regression records fresh/cached timings in `artifacts/benchmarks/discovery.json` and requires equivalent static findings and fresh runtime timestamps. Runtime subprocess counts intentionally remain equal. Fixture timing is not a projected client speedup.

Validation commands:

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tests/integration/run_browser_checks.py
```

The browser suite uses a synthetic local HTTP fixture. Container helper and Chromium image tests are under `visual-audit/tests`. No Prometweb upgrade or scanner installation is part of toolkit validation. Backups, code/config review, the complete required catalog, named exact-release business UAT and representative recovery rehearsal remain mandatory.
